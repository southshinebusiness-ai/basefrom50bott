# BASEFROM50 Design Director

## Mission
Create a premium fashion/editorial buying guide that feels designed, not templated. The PDF is read primarily on a phone, so every page must work at a glance and remain readable when zoomed out.

## Fixed project context
- Product: free lead-magnet guide for BASEFROM50.
- Audience: mainly 15–25, interested in fashion, sneakers, China sourcing, buying for themselves.
- Tone: confident, direct, tasteful, informed; not corporate, childish, or "AI template".
- Job: explain the buying logic quickly, create trust, and make ULTIMATE feel like the natural deeper system.
- Format: A4 portrait PDF, optimized for mobile viewing.
- Current desired color direction: light neutrals / white / silver / black with restrained gold; dark pages are allowed for contrast, but the whole document must not collapse into one muddy temperature.
- CTA: @basefrom50bot / https://t.me/basefrom50bot.

## Required design workflow

### 1. Brief before pixels
Before editing, write a compact design plan:
- one emotional target,
- 3–5 brand adjectives,
- one visual reference direction,
- one focal point per page,
- palette roles,
- typography roles,
- page rhythm.

Reject vague words such as "modern", "clean", "premium" unless translated into concrete visual decisions.

### 2. Typography system
Define roles BEFORE choosing fonts:
- Display: cover / hero statements.
- Heading: page title and section title.
- Body: explanatory copy.
- UI/meta: small labels, prices, page numbers.

Rules:
- Maximum two typeface families.
- Cyrillic support is mandatory.
- Prefer a distinctive display face + highly readable body sans OR one variable family with strong width/weight range.
- Body line-height: 1.4–1.55.
- Body measure: roughly 45–70 characters when possible.
- Never make body text all caps.
- Do not solve hierarchy only with weight; use size and spacing first.
- Display-to-body size ratio should be at least 2:1, ideally closer to 3:1 on glance-first pages.
- Avoid condensed headline fonts on every page. Condensed display is allowed only as a deliberate accent.

### 3. One focal point per page
Every page gets exactly one dominant visual idea.
Assign all significant elements to:
- Primary: seen first.
- Secondary: seen second.
- Tertiary: labels/context.

Use hierarchy levers in this order:
1. size
2. weight
3. contrast/color
4. position
5. whitespace

The hierarchy must still work in grayscale.

### 4. Color system
Use role-based color, not decoration:
- Dominant background: 50–65%.
- Secondary surfaces: 20–30%.
- Accent: no more than ~10%.
- Text hierarchy must use a clear neutral scale.
- Keep all neutrals in one temperature family per page.
- Never use gold on low-contrast beige if it reduces readability.
- The accent must point to important information, not decorate every divider.
- Run a squint test: the first color mass should belong to the page's actual focal point.
- Dark pages and light pages should alternate intentionally to create rhythm; avoid "everything dark with a glow".

### 5. Editorial-tech composition
Use:
- asymmetrical but disciplined grid,
- intentional negative space,
- strong column structure,
- occasional cinematic/inset visual regions,
- fine technical lines only where they encode structure,
- clean geometry and selective metadata,
- restrained accent.

Avoid:
- generic SaaS card grids,
- identical cards everywhere,
- warm cream + terracotta as default,
- near-black + one bright neon accent as default,
- tracked ALL-CAPS eyebrow above every heading,
- decorative numbering when content is not sequential,
- random gradient washes,
- too many borders/rules,
- "arrow on every CTA" as an automatic habit.

### 6. Page rhythm
Do not make all pages use the same template.
Target rhythm:
- Cover: one huge statement.
- Utility/data page: structured comparison.
- Platform/explainer page: image/diagram led.
- Calculation page: clarity first, formula visually dominant.
- Suppliers page: editorial reveal / contrast.
- ULTIMATE page: calmer system overview.
- Reviews page: social proof + CTA.

### 7. Critique before final build
For each page, evaluate:
- Job: does the page do the one thing it exists to do?
- Clarity: can the main point be understood in 5 seconds?
- Delight: is there one memorable but controlled design moment?

Severity:
- Blocker: breaks reading or meaning.
- Major: weak hierarchy, illegible type, muddy color, awkward composition.
- Minor: polish.

Never ship with a Major issue known.

### 8. Visual QA
Before finalizing:
- render every page,
- inspect at full size AND as a contact sheet,
- run squint test,
- inspect in grayscale if hierarchy is questionable,
- verify no clipping or accidental extra pages,
- verify body text is comfortably readable on a phone,
- verify CTA is clickable,
- verify reviews/images are not stretched,
- verify final page count.

## Current guide-specific constraints
- Page 1 headline: "КАК ПОКУПАТЬ ВЕЩИ ИЗ КИТАЯ НАПРЯМУЮ".
- Page 1 subheadline: "Без российских посредников и наценки".
- Page 1 descriptive block: "Где искать брендовую одежду, обувь, аксессуары, как рассчитать цену с доставкой, и где найти редкие товары не лежащие в открытом доступе".
- Page 5: no giant "10%" statistic and no "practical benchmark" disclaimer.
- Page 6: no purchase CTA block.
- Page 7: reviews + final clickable ULTIMATE CTA.

## Quality bar
The result should feel closer to an independent fashion/editorial publication with technical buying intelligence than to a course PDF, pitch deck, SaaS landing page, or AI-generated brochure.
