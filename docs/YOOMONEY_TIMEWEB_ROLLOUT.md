# YooMoney → Timeweb: безопасный ввод исправлений в работу

## Изменения

- Подпись `sign` проверяется через HMAC-SHA256. `sha1_hash` устарел с 18.05.2026.
- Проверяются валюта, статус, метка заказа и **withdraw_amount** (списано с покупателя). `amount` — зачислено за вычетом комиссии.
- Платёж и право доступа подтверждаются атомарно в SQLite; операция не может быть зачтена повторно для другого заказа.
- Выдача приглашения отслеживается отдельно от подтверждения оплаты; неудачные отправки повторяются.
- Кнопка «Я оплатил» обращается к официальному `operation-history` API ЮMoney (если настроен OAuth-токен с правом `operation-history`).
- Фоновая сверка проверяет неоплаченные заказы последних 7 дней раз в 5 минут; отправка приглашений повторяется ежеминутно (до пяти попыток).
- `/stats` считает `completed` и старый `success` одинаково.
- Ссылка на оферту отображается до покупки только при наличии действительного HTTPS URL в `OFFER_URL`.

## Что нужно проверить на Timeweb до обновления

1. **Текущий исходный код** на сервере может отличаться от GitHub; сравнить версии перед обновлением.
2. **Сохранить копию SQLite и .env** в защищённом месте, не в GitHub.
3. Убедиться, что `YOOMONEY_SECRET` совпадает с секретом из настроек HTTP-уведомлений ЮMoney.
4. Убедиться, что `YOOMONEY_TOKEN` — действующий OAuth-токен с правом `operation-history`; не путать с секретом уведомлений.
5. Проверить HTTPS endpoint: `https://<ваш-домен>/yoomoney/notify`. ЮMoney разрешает один URL уведомлений на кошелёк. Текущая инструкция DEPLOY.md открывает только SSH и **не настраивает HTTPS reverse proxy**, поэтому это надо проверить отдельно.
6. `curl -fsS http://127.0.0.1:8080/health` на сервере должен отвечать `ok`. Это проверяет только локальный HTTP, а не внешний HTTPS.
7. `OFFER_URL` задавать **только после публикации** финальной оферты с данными продавца.

## Ввод изменений

- Остановить сервис, сохранить БД, проверить конфигурацию и синхронизировать код из проверенной ветки.
- Установить зависимости, запустить тесты, запустить сервис и проверить логи.
- Проверить доступность внешнего HTTPS endpoint.
- В настройках ЮMoney нажать «Протестировать» (тестовый webhook не создаёт платежа).
- Сделать **реальную тестовую покупку** с отдельного аккаунта на сумму, выставленную в тестовом сценарии. Не снижать цену на основном боте без отдельного согласования.
- Проверить списание, сохранение операции в SQLite, автоматическую отправку ссылки, одобрение заявки и статистику.
- Имитировать временную ошибку отправки в тестовом окружении и проверить повторную доставку.
- Убедиться, что старые покупатели и их доступ сохранились.

## Диагностика

- Нет webhook: проверить HTTPS, настройки ЮMoney, секрет и доступность Timeweb.
- Неверная подпись: проверить `YOOMONEY_SECRET`; с 18.05.2026 нужен `sign`, а не `sha1_hash`.
- Нет резервной проверки: проверить `YOOMONEY_TOKEN` и scope `operation-history`.
- Платёж подтверждён, ссылка не пришла: проверить delivery_status, права бота на создание приглашений, доступность Telegram.
- Никогда не логировать OAuth-токен, секрет, банковские данные или полный payload webhook.
